# Required Link loss, simulator Hold and RTC shutdown

Review of 23 November 2026. The fault injection deliberately disconnected the controller's woofer output from the GPI2 simulator. The test supplied the trigger. Three separate software behaviors determine what happens next.

| Finding | Priority | Affected delivery | Disposition |
| --- | --- | --- | --- |
| F1. A missing required correction prevents the simulator from servicing Hold during its lockstep wait. | High for confirmed fault Hold | Released AdaptiveOpticsSimPipeWireHIL 0.5.11, shared by instruments using managed lockstep | Confirmed limitation of V1 fault revocation. Preserve graceful Pause and give the RTC and shared source an explicit way to abandon an exchange when required. |
| F2. The candidate services Hold during the wait but can discard a complete, valid correction during ordinary Pause. | Release blocker | Local HIL candidate `1b5b986` with AdaptiveOpticsSim `018b56ba` | Confirmed. | F3. A failed Quit can restart Hold against a retired source and hide the first failed shutdown effect. | High for recovery and fault diagnosis | Released PipeWireAORTC 0.7.29 | Confirmed in the RTC and reproduced independently. Preserve the first shutdown failure and use exact owner retirement evidence in recovery. |

These findings affect software an installed session actually uses. The first installed faulted run proves one instance of failed Quit. Its journal cannot identify the first failed Quit effect. Three fresh installed controls on the same software accepted Quit, including a matched untraced systemd stop after the same woofer fault. The historical failure is real and conditional. Its original cause remains unresolved. The evidence below distinguishes the trigger, the source acknowledgement, the operator's Quit receipt and the operating system's cleanup.

## What was lost

GPI2 has three required corrector outputs. The test removed exactly one admitted PipeWire Link, from `gpi2-jfg-frame-graph:woofer` to `simulator-woofer:input_1` (ID 253, serial 254 in that invocation). The registry confirmed removal. MediaSession revoked admission, requested Hold, and withdrew the remaining declared Links as part of fault handling. The count fell from 31 to zero. This was one injected topology change followed by a deliberate shutdown of the topology. There is no observed spontaneous transport loss, buffer overflow, or set of 31 independent failures. [Installed fault receipt](evidence/verified-hold.json)

In the same invocation the optional display ingress had already been detached and reattached. Both endpoints survived and the display received fresh frames after reattachment. The required admission stayed Running. In a separate controlled replay, all 62 command triples matched byte for byte across the observer profiles. [Command comparison](../../validation/gpi2-mean-pupil-intensity-20261122/README.md#science-across-viewer-loss-and-attachment)

A GUI dropping its latest-value sample, an intact Link carrying no new command, and a removed required Link have different semantics. With an intact silent Link, the exchange can time out waiting for the command. Only an actual required-object loss invokes the registry loss path directly. An operator unlink or an owner losing its required endpoint can invoke the same admission policy outside a test. The evidence measures no operational incidence. [Admission policy](../../operations.md#rtc-dev-021--admission-and-coherent-lifecycle) · [Registry and Link implementation](../../../src/media_session/objects.jl)

## F1 and F2. What Hold owes the science loop

Each exposure uses the previously adopted correction and can have one outstanding response. On multiple command ports, adoption is atomic for the same generation and sequence. In the released shared simulator, ordinary source control runs between exchanges. If a command is missing, the owner waits inside the exchange while the stop request is waiting to be consumed. In the earlier managed GPI2 run the request reached the simulator socket, the RTC's fault cleanup expired without its matching stopped acknowledgement, and the simulator later timed out waiting for the command set. That earlier managed run used RTC candidate `7af920a`. The baseline private-core test bundle calls the new `hold_requested` keyword, which the released HIL rejects before that exchange runs. The behavioral baseline comes from the managed trace and the released owner loop. The candidate private-core tests demonstrate both a missing single command and a partial three-port response. RTC-DEV-025 allows an unconfirmed control to end in Fault with supervised cleanup. The released runner honors the graceful adoption rule. What V1 lacks is a bounded, confirmable way to request abandonment when a required response cannot arrive. [Earlier managed trace and cohort](../../validation/gpi2-mean-pupil-intensity-20261122/README.md#installed-gpi2-source)

The candidate lets the owner consume control during the wait. It can retire one outstanding response, keep the acquired exposure and model time, preserve the last fully adopted correction and reject a late response for the retired sequence. In the instrumented GPI2 run the original source acknowledged stopped Run token 27. Re-reading the same source’s published properties 4.442 seconds later found the same retained acknowledgement and stopped cursor at generation 1, exposure 46. This was a property recheck, with no new Query token or continuous measurement. The token correlates a control request and its acknowledgement. It is independent of the exposure number and Link ID. [Installed Hold receipt](evidence/verified-hold.json)

**Ordinary Pause requires a different decision.** RTC-DEV-025 requires outstanding adoption before Pause acknowledges and requires the adopted cursor. Both normal session Stop and fault compensation issue `HoldSources`, which sends V1 Run with `running=false`. At the simulator this becomes the same interruption predicate. At HIL `src/exchange.jl:1285–1309`, interruption after all command ports have become ready can still enter the discard branch before adoption. The controller cannot encode its reason in that V1 boolean. The external HEART simulator also has an explicit finish-outstanding-exchange Pause contract. [Simulator control contract](../../operations.md#rtc-dev-025--acknowledged-simulator-admission-and-controls) · [HEART contract](../../operations.md#rtc-dev-028--external-heart-simulation-deployment) · [Session transitions](../../../src/media_session/machine.jl) · [Source effects](../../../src/media_session/effects.jl)

A paired private-core experiment created fresh three-port producers, kept every Link intact, and waited until all three matching responses were staged. Only the controlled Hold predicate differed. Exposure 1 was acquired in both runs. The resulting correction for the next exposure was:

| --- | ---: | --- | --- | --- |
| Continue | 1 | 22, 24 | 63, 66, 69 | 124 |
| Pending stopped Run | 0 | 10, 10 | 20, 20, 20 | 30 |

All 13 assertions passed. The experiment exercises real native command inputs and the model boundary with a controlled interleaving. The normal Stop mapping to the predicate is established by source inspection. The run gives a counterexample to the proposed Pause semantics with a healthy controller. It does not estimate how often a human Pause lands there. The earlier 145 native assertions for missing/partial commands, late packets, resume and reset establish other behaviors and still stand. ### The last exposure can look like a successfully completed finite run

In a second paired experiment the real managed simulator owner ran with a one-exchange limit and native Run, stopped Run and Query controls. A normal run adopted command 1. In the other run the producer delivered the woofer and tweeter responses and withheld tip-tilt. A stopped Run arrived while the source waited. The candidate retained all three initial corrections (active command 0), wrote a final operational report with `sequence=1`, `completed=true` and an empty failure list, and acknowledged the stop. A **new correlated Query** also reported completed. The released RTC’s snapshot validator and source-end predicate accepted it. The 31 assertions exercised real owner execution, report publication and production validation functions on a private core. The probe did not drive a whole instrument session or a calibration campaign. ## F3. What a failed Quit actually tells the operator

In the observed GPI2 fault, source and graph Hold and Link withdrawal completed. The state machine can also reach a settled Fault after an unsuccessful graph Hold or Link withdrawal, so the individual effect receipts matter. An authorized Quit from that state still has work to do. It requests source Hold, graph Hold, shutdown of graph owners, Link withdrawal, source shutdown, shutdown of remaining bootstrap owners, removal of controls and publication of the terminal Quit receipt. With live owners this procedure can complete. Link withdrawal empties the Link records after a server synchronization and verifies their absence. It does not discard all captured source or owner identities. [Quit sequencing](../../../src/media_session/machine.jl) · [Link withdrawal](../../../src/media_session/objects.jl)

During bootstrap shutdown, the RTC verifies the owner and its process provenance, then fences its data and control objects out of the active capture table before requesting shutdown. It retains the exact bootstrap endpoint while waiting for the correlated terminal receipt. The data endpoint may already be ineligible for new commands while bootstrap retirement is still unconfirmed. The acquisition binding can report terminal retirement. The simulator's V1 `SourceControlBinding` has no corresponding retirement observation of its own and its process shuts down through a separate bootstrap binding. [Retirement and identity checks](../../../src/media_session/objects.jl) · [Source and bootstrap effects](../../../src/media_session/effects.jl) · [Binding controls](../../../src/media_session/controls.jl)

If a pre-publication Quit effect then fails or expires, the general fault handler starts again at `HoldSources`. It can try a scientific control against a source whose capture has already been fenced. The exact-identity check rejects it with `ArgumentError: object is not captured`. On this path the machine can disconnect before the operator receives a terminal reply. If the session already retained the required-Link fault, the first failure during Quit can disappear from the final diagnostic, which pairs the original Link fault with the later cleanup error. A client must treat an unconfirmed mutation as unknown. Systemd reaping all processes is evidence of resource cleanup only. [Failure handling](../../../src/media_session/machine.jl) · [Disconnect reporting](../../../src/media_session/session.jl) · [Lifecycle contract](../../operations.md#rtc-dev-004--basic-lifecycle)

A deterministic probe drove the released state machine, retired the source capture and executed the real Hold identity check. An injected bootstrap timeout during `ShutdownOwners` and an injected inventory failure during `RemoveControls` produced identical final diagnostics after a prior required-Link fault. With a healthy starting session the first injected failure survived and the same secondary error followed. The 81 assertions use controlled effect completions. They prove information loss without assuming either injected cause occurred in GPI2. [Policy probe](evidence/retired_source.jl) · [Three outcomes](evidence/retired_source.log)

### Matched installed GPI2 comparison

Three fresh invocations used the same sealed GPI2 CPU arm, simulator package images, released RTC image and host placement. Each had a private core and unique systemd units. The optional analysis service was configured in all three. The added display client and socket trace from the original run were absent. Each row has its own verified resource cleanup. [Comparison receipts and systemd timing](evidence/installed-comparison.json)

| State before shutdown | How Quit entered | Source and controller evidence | Terminal outcome |
| --- | --- | --- | --- |
| Running, all 31 Links | Ordinary systemd stop | Run token 11 acknowledged, exposure 2 observed | Native Offline, RTC exit 0 |
| Settled Fault after required woofer removal | Direct native session client while systemd unit was active | Controller stopped, zero Links, stopped token 18, generation 1/exposure 16 rechecked after 2.551 s | Direct client received Offline, RTC exit 0. Later ExecStop found the main process already gone. |
| Settled Fault after the same required woofer removal | Ordinary systemd stop | Controller stopped, zero Links, stopped token 18, generation 1/exposure 13 rechecked after 2.420 s | Stop helper confirmed native Offline, RTC exit 0 |

Thus both shutdown entry paths worked in the installed fault state. In the matched systemd case the optional pupil-flux analysis unit also received a concurrent stop and exited before native Quit. That ordering occurred on both a passing and a failing run. The original instrumented systemd failure still counts as an operator command failure. Its recurrence does not follow simply from the Link loss or the use of systemd. The trials changed multiple conditions relative to the original, including tracing, display activity and timing. They cannot attribute the original failure to any one of them or establish a failure rate. [Original and matched journal excerpts](evidence/systemd-journal-excerpts.json)

The private-core controls use a fixture to establish admission, then drive the production native session client, RTC state machine and effects. The source and graph respond on software endpoints. Their purpose is to distinguish causes, so a single native control attempt per fixture is sufficient to refute a universal Fault-to-Quit failure. These trials give no service-level reliability or shutdown-latency estimate.

In the original installed failure the manager journal showed settled fault cleanup before systemd requested stop. Optional analysis exited around the start of systemd stop. The simulator process exited before the RTC reported the capture error. Process exit does not establish that the RTC received its bootstrap acknowledgement. A parameter owner later reported an expired native owner request. The RTC sets its internal Quit deadline at admission to the earlier of its five-second effect budget and the caller deadline. The systemd client's larger budget includes other work. The first failed effect, its target and the RTC admission time were absent from that trace. An owner deadline, cold dispatch, and supervisor ordering are distinguishable hypotheses. This run does not establish which first failed. ## Recommended changes and verification gates

1. **Give the shared simulator two explicit outcomes for an outstanding exposure.** Ordinary Pause stops new exposures, finishes and adopts the outstanding coherent command, then acknowledges the applied cursor. A fault with a permanently unavailable required command needs an explicit bounded way to abandon that response, retain the previous applied correction, and acknowledge the acquired and last-adopted positions. An interrupted final exposure must remain distinguishable from successful completion throughout the saved report and the RTC’s source-end decision. Keep V1 Pause semantics for existing owners. MediaSession owns the admitted topology and decides when required-path loss warrants abandonment. Give that decision a declared, negotiated source-control operation. A generic Fault or a temporarily unready port cannot supply this intent on its own. Let the single exchange owner order adoption and revocation. Preserve a command committed before revocation, and reject later responses for the retired exposure. A peer without the capability can report unconfirmed revocation and enter supervised cleanup. A grace period or a test that only asks whether all ports are ready at one instant cannot distinguish a delayed valid command from a permanently missing one.
2. **Record the first failed shutdown effect before starting compensation.** Preserve the original fault, the first Quit failure, and any secondary cleanup failure. Include effect, owner/endpoint incarnation, ticket, admission time, deadline, and whether the mutation was submitted or acknowledged. Use monotonic times. Capture the evidence on the control path, outside frame processing. This is the smallest change that can tell the operator which owner and deadline to investigate in another installed failure.
3. **Make shutdown respect progress already proved for each owner.** Use the existing owner and capture records to associate each source control with its bootstrap. Distinguish a confirmed Hold, an endpoint fenced during retirement, a correlated terminal acknowledgement and an unknown outcome. Only reuse a Hold proof for the exact same incarnation and generation with no intervening Run. Once control has been fenced, use a remaining, unattempted bootstrap action only if its contract permits it. A submitted shutdown with an unknown outcome must never be replayed. Use exact-incarnation supervised cleanup when proof is unavailable. Preserve the single Quit deadline, the separately bounded compensation path, and the operator's unknown outcome. Admit again only with fresh validated incarnations.
4. **Report outcomes independently in the harness.** Record display continuity, required Link identity, source Hold/cursor, native Quit receipt, and reaping of the exact unit invocation. Clean up test-owned files even when an assertion fails. Keep one optional-tap and one required-path case in the installed smoke test. Put race/interleaving and lost-receipt cases in deterministic shared tests. A transport change, a deeper observer queue, or a new polling runner would leave both control defects intact.

| Boundary to verify before promotion | Acceptance evidence |
| --- | --- |
| Shared lockstep, normal Pause | Before publication, after publication with a delayed complete response, and with all ports already ready. No further exposure after ACK. Exactly one adoption of the outstanding valid set. A resumed exposure sees that correction. |
| Shared lockstep, fault revocation | Missing scalar, partial named set and stale/late reply across resume or reset. Keep previous applied values on every port, fence the retired sequence/generation, and acknowledge within the declared budget or report unknown. Check stalled output after a committed model step separately. |
| Finite exposure count and calibration | Interrupt the final outstanding exchange. Distinguish final exposure acquisition from final correction adoption, saved artifacts and a successful finite run. Verify what an external report consumer accepts. |
| RTC terminal cleanup | Exercise both healthy and already-faulted sessions. Fail before submission, after endpoint fencing but before terminal ACK, and after confirmed owner retirement. Preserve first failure, reject stale identity, return Offline only with proof, and verify a separately admitted fresh invocation. |
| Installed GPI2 | Exercise optional detach/reattach, required output loss, ordinary Pause and both direct native and systemd Quit. Identify the first failed effect if any, verify operator reply and process cleanup separately. |
| Other owner types | Verify graceful Pause for a V1-only source and a genuinely missing response for a capable owner. For a graph holding an input loan, check fault teardown ordering. Earlier SPIDERS work found an input-buffer lifetime issue on orderly Quit. This GPI2 output-loss result does not qualify that case. ## Scope and provenance

The reviewed RTC release is `01c55371` (0.7.29, package tree `3dc5cbca8c11f5035a1ac8a4ef11a26cf340d5a8`). This review worktree started clean at `23469636`, whose changes since the tag are documentation. The prepared GPI2 CPU arm used instrument `356f4411`, FilterGraphPipeWire 0.5.11, Julia 1.13.4, PipeWireAO.jl 0.9.6 and the AVX2 4.0.8 SDK. Candidate model and HIL runtime files matched `018b56ba` and `1b5b986`. The prepared private environment retained the earlier package version labels to satisfy its sealed manifest. These candidate source changes have not been promoted by this review.

F1 and F2 apply to instruments using this managed lockstep implementation, including a single-corrector instrument. The free-running source takes a different path. External HEART has its own provider and shares the graceful-Pause contract. F3’s failure retention is in shared MediaSession policy. The capture error requires a binding and retirement state in which the scientific control is no longer usable.

This is software verification on isolated PipeWire cores and user services. It establishes behavior of the shared lockstep and session implementations under the documented conditions. It does not establish spontaneous fault frequency, worst-case stop time, physical mirror position or hardware fail-safe behavior.
