## Runtime source copying and inventory code

`src/science_export.jl` defines `RUNTIME_ENTRIES = ("Project.toml", "Manifest.toml", "src", "test", and four top-level WirePlumber CLI/launcher/install/configuration Julia files)`. `copy_deployment_runtime` removes legacy launcher/service artifacts, copies these entries to `<package>/julia`, and copies deployment `hil` and `templates` resources while ignoring `.git`, `__pycache__`, test-prefixed HIL files, and `.py` files. `RESOURCE_ENTRYPOINTS` is empty; the session service template is explicitly copied. It does not copy the sibling scientific package source trees into this runtime bundle. `orchestration_sources()` enumerates and SHA-256 hashes the declared runtime entries except package tests, plus all deployment resources; it rejects symlinked operational files/directories. `source_relative_path` in package root maps a file under package root to `julia/<relative path>` and rejects outside paths.

`src/deployment_configuration.jl::validate_runtime` checks required package files/resources and iterates installed `src` for completeness against the current package's `src`; it also checks deployment templates/HIL completeness. WirePlumber runtime staging in ScienceExport copies upstream runtime scripts, executable/library/modules and excludes upstream `tests`/`test` directories. These are the principal cross-owner copy and runtime-inventory locations found by static search.
